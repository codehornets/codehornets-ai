## Lock Keys Hierarchy

All locks use prefix: funnel-agents:lock:

1. scheduler:check-due-tasks
   - System cron job
   - Prevents multiple instances from checking due tasks simultaneously
   - TTL: 50 seconds

2. scheduler:cleanup-executions
   - System cron job
   - Ensures only one instance runs cleanup
   - TTL: 10 minutes

3. scheduler:task:{taskId}
   - Per-task execution lock
   - Prevents duplicate execution of same task
   - TTL: Dynamic (task timeout + 10s buffer, min 60s)

4. workflow:dispatch:{workflowId}:{taskId}
   - Workflow dispatch lock
   - Prevents duplicate workflow executions
   - TTL: Task timeout + 5s

5. report:dispatch:{reportId}:{taskId}
   - Report generation lock
   - Prevents duplicate report generation
   - TTL: Task timeout + 5s

6. agent:dispatch:{agentId}:{taskId}
   - Agent task creation lock
   - Prevents duplicate agent tasks
   - TTL: Task timeout + 5s

7. custom:dispatch:{taskId}
   - Custom task execution lock
   - Prevents duplicate custom executions
   - TTL: Task timeout + 5s

## Deployment

### Zero Downtime Deployment
1. No database schema changes
2. No breaking API changes
3. Graceful degradation when Redis unavailable
4. Can deploy without Redis (single instance mode)

### Deployment Steps
1. Ensure Redis is running
2. Configure REDIS_URL environment variable
3. Deploy updated scheduler service
4. Verify logs show "Redis connected successfully"
5. Scale to multiple instances (if needed)

### Rollback
If issues occur:
1. Scale down to single instance (works without locks)
2. Or restart Redis
3. Check environment variables
4. Review logs for connection errors

## Performance Impact

- Lock overhead: 2-5ms per operation (Redis RTT)
- Memory: ~100 bytes per active lock in Redis
- CPU: Negligible (async I/O)
- Network: 2-4 Redis commands per task execution
